## Findings considered and rejected

So these are not re-audited next run:

- **Invoice wire mapping "only tested against the fake" (TESTS-01/02)** — false
  positive. `tests/unit/rest-invoices.test.ts:243-261` pins `addInvoiceItem`'s
  ×100 wire scaling, `:47-69` pins the ÷100 read, and `:191-217` pins the
  discount/tax field-name remap — all against a real `fetch` mock, independent
  of the fake. The fake operating in port-level (minor) units is correct.
- **Nonce-rotation TOCTOU (CORRECTNESS-05 / TESTS-04)** — false positive. Both
  `updateConfirmationNonceHash` and `markConfirmationUsed` are `UPDATE … WHERE
  id=? AND status='pending'`; under SQLite's single-writer, a concurrent confirm
  wins and the rotation no-ops. (Corroborates a prior "verified false-positive.")
- **Loser-confirm `result_json` race (CORRECTNESS-03)** — rejected. The loser
  correctly gets `409 already_used`; the winner's receipt + the idempotency
  ledger + the audit log are the source of truth.
- **README omits RETENTION_DAYS (DOCS-01)** — rejected. `README.md` defers to
  `.env.example` as the canonical env list, whose completeness is test-pinned via
  `ENV_SCHEMA_KEYS` (`src/config.ts`).
- **madge CI claim unverified (DOCS-02)** — rejected. `.github/workflows/ci.yml`
  runs `npm run cycles`; the CLAUDE.md claim is accurate.
- **Express 4→5 / Zod 3→4 (DEPS-01/02)** — rejected. Both are maintained; real
  migration cost, no concrete benefit now. Revisit if an EOL/security cutoff
  appears.
- **Security audit — zero findings.** Tenant isolation (workspace+admin
  scoping), AES-256-GCM (per-ciphertext IV, auth-tag verified), the signed
  `SameSite=None;Secure;Partitioned` cookie, IDOR on confirm/cancel/undo, the
  "model never sees secrets" invariant, and error-response hygiene were all
  verified sound. No remediation.
- **Money/wire audit — clean.** All 13 money paths + the GET-then-PUT full-body
  replacements + the discount/tax ×100 remap + idempotency keys check out.
